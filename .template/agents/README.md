# Agents

Canonical role prompts. One file per role, **without host-specific frontmatter**: the body is the
instruction set, and the bootstrap generates the adapter each tool needs.

## Available roles

| Role | File | Purpose |
|---|---|---|
| `analyst` | `analyst.md` | Analysis and planning (OpenSpec) |
| `engineer` | `engineer.md` | Implementation (TDD) |
| `reviewer` | `reviewer.md` | Read-only code review |
| `qa-analyst` | `qa-analyst.md` | Functional testing |
| `doc-writer` | `doc-writer.md` | Technical documentation |

Optional roles live in packs (`.template/packs/<pack>/agents/`) and are copied here only when the pack
is activated.

## Naming

- **Role, not architecture.** The file name describes what the agent does, not the style it applies.
- kebab-case, matching the ID used in `AGENTS.md`.

## Host adapters

| Host | Where the adapter goes | How it is generated |
|---|---|---|
| OpenCode | `.opencode/agent/<role>.md` | Frontmatter (`description`, `mode`, `model`, `permission`) + canonical body |
| Claude Code | `.claude/agents/<role>.md` | Frontmatter (`name`, `description`, `tools`, `model`) + canonical body |
| Codex | *(no subagents)* | The roles are emulated through `AGENTS.md` and the role announcement |

Adapters are generated by the bootstrap from `.template/hosts/<host>/`. They are not edited by hand:
change the canonical prompt here and regenerate.

## Writing rules

- **Language:** `language.agent` (English by default).
- **No architecture mandates.** Reference `AGENTS.md` § Architecture; the project decides its stance.
- **No hardcoded commands.** Reference the commands declared in `AGENTS.md`.
- **No domain terms.** Use placeholders.
- **No host syntax.** No `/command` or `$command` in the body.
- **Announce the role** at the start, so multi-role sessions stay explicit.
- **Keep the contract short.** Long procedures belong in skills.
