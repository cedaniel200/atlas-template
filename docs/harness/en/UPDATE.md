# Updating the harness

> **ATLAS** is a **scaffold**, not a runtime dependency. Updating is optional, explicit and **never destructive**.

---

## When

- A new template version exists and you want its improvements (skills, gates, prompts).
- **Do not update mid-change**: finish or archive the change first.

## What you need

- `.atlas/state.json` with `template_source` (url + commit) and `.atlas/manifest.json` (generated by the bootstrap).
- `state.stacks` (multi-stack), `state.packs` and `state.readme` (if present) to preserve the configuration.
- **Node 20+** (the only runtime the harness assumes).
- A copy of the new template (clone or checkout of the tag/commit).

## Steps

1. **Get the new template** in a temporary directory:

   ```bash
   git clone <template-url> /tmp/new-template
   git -C /tmp/new-template checkout <tag-or-commit>
   ```

2. **Run the update** from your project root:

   ```bash
   node .atlas/scripts/actualizar-arnes.mjs --template /tmp/new-template
   ```

   - `owned` (AGENTS.md, config, docs, adr, specs) → **never overwritten**.
   - `generated` (adapters, `opencode.json`, `CLAUDE.md`) → **regenerated** (adapters with resolved placeholders).
   - `managed` (skills, prompts, schemas, active packs) → replaced **only if you did not modify it**; otherwise `<file>.new` is written.
   - Before writing, it backs up what it replaces to `.atlas/backups/<timestamp>/`.
   - **It rewrites `manifest.json` and `state.json`** (version, commit, hashes) so the next update does not report false conflicts.

3. **Resolve conflicts** (`.new`):

   ```bash
   diff -u <file> <file>.new   # merge by hand
   rm <file>.new
   ```

4. **Validate**:

   ```bash
   node .atlas/scripts/validar-manifiesto.mjs
   node .atlas/scripts/validar-contrato.mjs
   node .atlas/scripts/validar-perfiles.mjs
   openspec doctor && openspec context
   ```

5. **Commit**: `chore(harness): update to <version>`.

## What it does NOT do

- It does not overwrite `owned`.
- It does not delete files: if the template removes one, it **reports** it.
- **Packs**: active packs are updated as `managed` (if you did not modify them); inactive packs and the `.atlas/packs` catalog are not touched. Enable/disable them by hand.
- It does not resolve conflicts for you.

## Rollback

Copy the files back from `.atlas/backups/<timestamp>/`.

## For agents

The **`update-harness`** skill describes the same flow. Use the script; do not improvise hashes or overwrite `owned`.
