## Adapter generation

The prompts in `.template/agents/<role>.md` are the canonical source, **without host frontmatter**.

| Host | Adapter | Minimum frontmatter |
|---|---|---|
| OpenCode | `.opencode/agent/<role>.md` | `description`, `mode: all` |
| Claude Code | `.claude/agents/<role>.md` | `name`, `description` |
| Codex | — | No subagents |

`opsx-*` commands are **not** maintained by hand: `openspec update --tools <host>` regenerates them.

## Known degradations

| ID | Limitation | Impact | Mitigation |
|---|---|---|---|
| C‑1 | Codex has no subagents | No separate `engineer`/`qa-analyst` agents | `AGENTS.md` defines the role protocol; the role announcement still applies |
| C‑2 | `disable-model-invocation` is not in the Agent Skills spec | Some hosts may auto-invoke a skill that should be manual | Documented; a pack that uses it is marked as host-dependent |
| C‑3 | Symlinks on Windows require developer mode | `.claude/skills` broken on Windows | Static copy + re-run the bootstrap when adding skills |
| C‑4 | `openspec init` may rewrite `AGENTS.md` | Loss of the project contract | Backup + `diff` + manual merge (`.template/BOOTSTRAP.md` § 0.4) |
| C‑5 | Command wrappers depend on the OpenSpec version | Outdated wrappers after an upgrade | Regenerate with `openspec update --tools <host>` |
| C‑6 | Claude Code and Codex load nested `AGENTS.md` differently | Subdirectory rules are not uniform | Core at the root only; nesting is documented per project |
| C‑7 | MCP is not portable | Each host has its own format | `.env.example` generated by the bootstrap + per-host block in `.template/hosts/` |
| C‑8 | Agent lifecycle hooks do not exist in Codex | Automations that depend on them do not work | Agent hooks are optional; the flow lives in skills and instructions |
| C‑9 | Two instruction sources (`CLAUDE.md` and `AGENTS.md`) | Contradictory rules | `CLAUDE.md` contains **only** `@AGENTS.md`; never duplicate |

## Hooks: agent vs. git

| Type | Where it lives | Portability |
|---|---|---|
| **Agent hook** (session lifecycle) | Plugin/hook of each tool | Low: OpenCode and Claude Code only |
| **Git hook** (`pre-commit`, `post-commit`) | `.githooks/` + `core.hooksPath` | **High: works in all three** |

The core does not depend on agent hooks. If a project uses gitleaks or Engram, it does so through git
hooks, which are independent of the host tool.

## Shell and operating system

The ritual uses **POSIX** commands (`sh`, `grep`, `diff`, `mkdir`). On Windows run it from
**Git Bash or WSL** (recommended), not from `cmd.exe`.

| Environment | Shell | Manifest hash helper |
|---|---|---|
| macOS / Linux | POSIX (`sh`) | `.template/scripts/sha256.sh` |
| Windows + Git Bash / WSL | POSIX | `.template/scripts/sha256.sh` |
| Native Windows | PowerShell 5.1+ | `.template/scripts/sha256.ps1` |

- **Do not** call `certutil` or `Get-FileHash` directly: they emit **uppercase** and a different
  format (`certutil` also adds a header and footer) → the manifest becomes incomparable and the
  update reports **false drift**.
- **EOL:** the hash is computed on the file on disk. The generated `.gitattributes` sets
  `* text=auto eol=lf`, so the hash is comparable across systems.
- If neither a POSIX shell nor PowerShell is available, the ritual must **stop** and ask the user.

## Verified sources

- **OpenCode** — *Agent Skills*: `.opencode/`, `.claude/`, `.agents/` paths; frontmatter
  `name`/`description`/`license`/`compatibility`/`metadata`; keys `opencode/slash` and
  `opencode/autoinvoke`.
- **Claude Code** — `@file` import in `CLAUDE.md`; `.claude/skills` with hot-reload and symlink support;
  `.claude/agents/` for subagents.
- **Codex** — shared skill discovery from `.agents/skills`; mention with `$` or `/skills`; no subagents.
- **OpenSpec 1.5** — `openspec init --tools <list>`; per-tool command adapters; `spec-driven-with-adr`
  schema resolved from `openspec/schemas/`.
